# Boorstar

Rust로 만든 개인 에이전트·하네스 관리 앱. 화면은 egui/eframe으로 그리며, React·Electron·WebView를 사용하지 않습니다. macOS 우선입니다.

## 실행

```sh
cargo run --locked
# Finder에서 열 수 있는 앱 만들기
make package
```

패키지: `dist/Boorstar.app`. 현재 Mac 아키텍처로 빌드하며 로컬 ad-hoc 서명입니다. 배포용 공증·자동 업데이트는 포함하지 않습니다.

## 사용 흐름

1. **레포 연결**에서 로컬 Git 레포 경로를 입력하고 연결합니다. 목록 제거는 레포 파일을 삭제하지 않습니다.
2. **하네스 연결 경로**에서 설치된 harness-core의 `bin` 폴더를 확인합니다. 설치 캐시를 자동 탐색하지만, 갱신 후 경로가 바뀌면 여기서 다시 지정합니다.
3. **도입 상태 점검**으로 레포의 검증 명령·지침·CI 준비 상태를 확인합니다.
4. **하네스 설정**에서 전역·레포별 위임 모드와 전역 중지를 저장합니다.
5. **에이전트**에서 모델·effort를 저장한 뒤, 작업 요약·명세를 입력해 위임합니다.
6. **모니터링·분석**에서 루프 상태·최근 검증·위임 결과·모델 사용량을 확인합니다.

## 적용 범위

| 설정 | 적용 대상 |
| --- | --- |
| 앱의 레포 목록·연결 경로 | Boorstar |
| 전역·레포별 위임 모드, 전역 중지 | 기존 boo-harness와 공유 |
| Claude·Codex 후보의 모델·effort | Boorstar에서 시작하는 다음 위임만 |
| 실행 중인 에이전트 | 변경하지 않음 |

모델을 저장하면 앱 설정에 유지하고, 위임 시 기존 Python `dispatch` 모듈의 후보를 **해당 자식 프로세스 안에서만** 바꿉니다. 하네스 소스·설치본·터미널·스킬의 기본 모델은 수정하지 않습니다. Python 코드는 기존 하네스 연동용으로 호출하며 앱 화면·설정·파일 처리·프로세스 관리는 Rust입니다.

모델 이름의 실제 계정 접근 권한은 앱에서 보증하지 않습니다. 기존 하네스가 반환한 실행 영수증과 완료·검증 결과를 구분합니다.

| 모드 | 동작 |
| --- | --- |
| off | 외부 추천·워커 실행 없이 기존 방식으로 복귀 |
| observe | Jev로 작업 요약을 보내 추천만 조회 |
| apply | Jev 추천에 따라 Orca 워커 시작 |

observe·apply에는 Jev 자격증명이, apply에는 실행 가능한 Orca와 등록된 레포가 필요합니다. 인증은 기존 CLI 환경을 사용합니다. 앱에서 키를 읽거나 저장하지 않습니다. Finder로 실행하면 터미널의 PATH·환경변수를 상속하지 않을 수 있으므로, 기존 CLI 환경이 필요한 위임은 터미널에서 앱을 실행하세요. 실행 여부가 불명확하면 자동 재시도하지 않습니다.

## 데이터와 해석

- 앱 설정: `~/Library/Application Support/Boorstar/config.json`
- 하네스 홈 기본값: `~/.claude`
- 계측 기본값: `<하네스 홈>/harness-metrics.jsonl`
- 앱 종료 후에도 기존 하네스는 독립적으로 작동합니다.
- 모니터링은 5초 간격으로 상태 파일·계측을 다시 읽습니다. 표시되는 활성 상태는 마지막 파일 기록이며 프로세스 생존 확인이 아닙니다.
- 완료 조건·단계는 조회 버튼을 누를 때 기존 하네스의 판정을 가져옵니다.
- 분석 시작일은 로컬 날짜 기준이며 선택한 레포만 집계합니다. 문서만 바뀌어 검증을 건너뛴 통과는 제외합니다.
- 검증·루프 계측의 origin 레포명과 위임 계측의 절대 경로를 모두 연결합니다. 레포명만 있는 기록은 같은 이름의 워크트리를 함께 집계하며 경로별 분리는 확인할 수 없습니다.
- 위임 시작과 결과 검증 통과를 별도로 셉니다. repo가 없는 검증 기록은 dispatch_id로 실행 기록과 연결될 때만 포함합니다.
- 모델 사용량은 선택한 계측에 연결된 **세션 전체의 캐시 제외 토큰**입니다. 기간 내 소비량이나 실제 청구액이 아닙니다. 세션 기록이 없으면 미수집으로 표시합니다.
- 원문 대화·인증값·stderr·작업 영수증 전문은 화면에 표시하지 않습니다.
- 손상된 JSON은 오류로 알리고 덮어쓰지 않습니다. 설정을 저장할 때 알 수 없는 필드는 보존합니다.
- 128MB를 넘는 계측 파일은 나눠 연결해야 합니다. 첫 버전은 파일 기반 조회이며 DB나 백그라운드 서비스가 없습니다.

환경변수 `BOORSTAR_HOME`, `BOORSTAR_HARNESS_BIN`, `HARNESS_HOME`, `HARNESS_METRICS_PATH`로 초기 경로를 지정할 수 있습니다. 저장된 앱 설정이 있으면 저장값을 사용합니다.

## 검증

```sh
make verify-quick
# 설치된 하네스와 실제 계약 확인. 임시 설정·계측, off 모드로 실행한다.
BOORSTAR_HARNESS_BIN=/절대/경로/harness-core/bin \
  cargo test --no-default-features --test acceptance installed_harness_contract -- --ignored --exact
```

테스트는 임시 Git 레포와 설정을 사용하며 네트워크·유료 모델을 호출하지 않습니다. 앱 로직 테스트는 Rust에 있고 `tests/test_acceptance.py`는 기존 spec-trace가 인식하는 이름·JUnit으로 연결하는 테스트 실행 어댑터입니다. `JUNIT_PATH` 기본값은 `/tmp/boorstar-junit.xml`입니다.
